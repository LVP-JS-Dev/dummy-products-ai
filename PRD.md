# PRD (Root): Contract-first UI Monorepo

## 1. Цель системы

Создать монорепозиторий, в котором:

- UI Kit является формально специфицированной системой (contract-first),
- документация и витрина отделены от библиотеки,
- основной продукт использует UI Kit как зависимость,
- система пригодна для человеко- и машиночитаемого (agent-first) использования.

Проект используется как:

- портфолио-проект,
- демонстрация senior-level архитектурного мышления,
- база для агентной разработки UI.

---

## 2. Состав системы

Монорепозиторий состоит из следующих логических частей:

- `packages/ui-kit`
  Переиспользуемый UI Kit с контрактами, состояниями и машинной спецификацией.

- `apps/web`
  Основное приложение с предметным сценарием тестового задания (auth + products),
  которое потребляет UI Kit в продуктовом контексте.

- `apps/fumadocs`
  Документация и визуальная витрина компонентов на Next.js + Fumadocs.

---

## 3. Архитектурные принципы (инварианты)

### 3.1 Contract-first

- Контракты компонентов являются **единственным источником истины**.
- Типы, `states`, события (events) и спецификация выводятся из контрактов.
- Документация и приложения не определяют API компонентов.

### 3.2 States как публичный артефакт

- States являются частью публичного API UI Kit.
- States используются для:
  - документации,
  - примеров,
  - тестов,
  - агентного потребления.
- States валидируются контрактами.

### 3.3 Документация ≠ Source of Truth

- Документация отображает систему, но не определяет её.
- Fumadocs Story используется как docs-focused витрина, а не как тестовый фреймворк.

### 3.4 Чёткие границы пакетов

- Приложения импортируют UI Kit только через публичный API.
- Внутренние файлы пакетов не импортируются напрямую.
- Docs-зависимости не попадают в UI Kit.

---

## 4. Общие нефункциональные требования

- Простота запуска и понимания структуры.
- Минимальный, но выразительный стек.
- Предсказуемость изменений (no hidden magic).
- Возможность постепенного расширения без архитектурного слома.

---

## 5. Out of scope

- Полноценная замена Storybook.
- Собственная backend-инфраструктура, собственный auth-сервис, собственная database-инфраструктура, payments.
- Запрет не распространяется на интеграцию с внешними публичными API, если это требуется продуктовым сценарием `apps/web`.
- Маркетинговые или визуально сложные демо.
