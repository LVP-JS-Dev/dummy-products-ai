# PRD: Docs (`apps/fumadocs`)

## 1. Назначение приложения

`apps/fumadocs` — это документационное приложение на базе Next.js + Fumadocs, предназначенное для:

- человеко-читаемой документации UI Kit;
- визуальной демонстрации компонентов;
- интерактивных примеров через Fumadocs Story.

Приложение **не является**:

- источником истины по API компонентов;
- средой тестирования UI (в смысле Storybook / visual regression);
- местом определения новых props или состояний.

---

## 2. Архитектурная роль в системе

`apps/fumadocs` — потребитель `packages/ui-kit`.

Он:

- импортирует компоненты и `states` через публичный API;
- отображает их;
- не хранит собственные версии контрактов или примеров.

Любая логика, влияющая на shape props или допустимые состояния, не может находиться в `apps/fumadocs`.

---

## 3. Технологический стек

- Next.js (App Router)
- Fumadocs (MDX-based docs framework)
- Fumadocs Story (docs-focused interactive previews)

### 3.1 Ограничения стека

- Fumadocs MDX является ESM-only.
- Конфигурация Next должна использовать `next.config.mjs`.
- Документация ориентирована на developer experience, а не на end-user UX.

---

## 4. Структура приложения

Рекомендуемая структура:

```text
apps/fumadocs/
  content/
    components/
      button.mdx
      input.mdx
  src/
    stories/
      button.story.tsx
      input.story.tsx
  app/
  next.config.mjs
```

---

## 5. Контент (MDX)

### 5.1 Назначение MDX-страниц

MDX-страницы используются для:

- описания назначения компонента;
- объяснения его API;
- демонстрации допустимых состояний;
- встраивания интерактивных Story-блоков.

MDX **не используется** для:

- определения props;
- определения `states`;
- генерации данных для UI Kit.

### 5.2 Стандарт страницы компонента

Каждая страница компонента обязана содержать:

1. **Описание**
   - что это за компонент;
   - когда использовать / не использовать.
2. **API**
   - краткое описание props (без дублирования контрактов);
   - ссылки на спецификацию (schema / manifest).
3. **Examples**
   - визуальный список `states` из `@dummy-products/ui-kit`.
4. **Interactive**
   - один интерактивный блок `<story.WithControl />`.

---

## 6. Fumadocs Story

### 6.1 Роль Story

Fumadocs Story используется как:

- интерактивный playground;
- средство исследования props;
- дополнение к статическим `states`.

Story не заменяет `states` и не определяет допустимые варианты использования.

### 6.2 Технические требования Story (Next.js)

Для каждой Story:

- Story-файл обязан быть client component:

```ts
"use client";
```

- Story должен экспортироваться как `story` или иметь `name`, совпадающий с экспортом.
- В MDX Story рендерится как:

```tsx
<story.WithControl />
```

Story-файлы располагаются только в `apps/fumadocs`.

### 6.3 Источник данных для Story

- Базовые args для Story берутся из `states` UI Kit:

```ts
import { states } from "@dummy-products/ui-kit";
```

- Docs не создают собственные args и не дублируют `states`.

Допускается:

- выбирать один state как default для интерактивного Story.

---

## 7. Client boundaries (критично)

### 7.1 Принцип

- UI Kit может содержать server-compatible компоненты.
- Docs Story всегда client-side.

### 7.2 Правила

- Любой компонент, используемый в Story, должен быть совместим с client rendering.
- Story-файлы изолируют client-boundary, не протаскивая её в UI Kit.

---

## 8. Инварианты и запреты

Запрещено:

- определять новые `states` в docs;
- изменять shape props в Story;
- импортировать внутренние файлы `ui-kit`;
- добавлять бизнес-логику в MDX;
- использовать Story как единственный способ демонстрации компонента.

---

## 9. Допустимая эволюция

В будущем допустимо:

- добавлять новые MDX-страницы;
- расширять описания компонентов;
- добавлять ссылки на schema / manifest;
- добавлять дополнительные Story-блоки (но не вместо `states`).

Недопустимо:

- превращать docs в source of truth;
- хранить “умные” примеры, не отражённые в `ui-kit`.

---

## 10. Критерии готовности (DoD)

`apps/fumadocs` считается корректным, если:

1. Каждому публичному компоненту UI Kit соответствует MDX-страница.
2. Каждая страница использует `states` из `@dummy-products/ui-kit`.
3. На каждой странице есть `<story.WithControl />`.
4. Story-файлы являются client components.
5. Docs не содержат собственных контрактов или `states`.
6. UI Kit не имеет зависимости от Fumadocs или Next.js.
