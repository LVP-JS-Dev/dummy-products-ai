Эта страница суммирует архитектурные правила, которые удерживают систему
цельной.

## Contract-first поток

Проект использует односторонний поток истины:

- контракты задают API компонентов
- типы выводятся из контрактов
- states выводятся из контрактов
- docs и apps потребляют states

Docs и apps не определяют props или states. Если требуется менять API, сначала
обновите контракт и PRD.

## Источник истины

UI Kit — единственный источник истины для API компонентов:

- `packages/ui-kit` определяет контракты, компоненты и states
- `apps/fumadocs` документирует и визуализирует компоненты
- `apps/web` использует компоненты в продуктовых сценариях

Любое изменение API компонентов начинается в UI Kit.

## States — публичный API

States не являются демо-данными. Это часть публичного API, которая применяется
в разных местах:

- примеры в документации
- контрактные тесты
- входные данные для агентов и инструментов

States остаются сериализуемыми и валидируются контрактами.

## Generated артефакты должны быть актуальны

Сгенерированные схемы и manifest — это коммитимые артефакты. В репозитории
действует правило no-drift, поэтому перегенерация не должна создавать diff.

Ключевые пути:

- `packages/ui-kit/src/generated/`
- `packages/gen-api/generated/`

## Инвариант пагинации

Пагинация в продуктовых сценариях использует компонент `Pagination` из UI Kit.
Приложения не вводят альтернативные контролы с другим API.
