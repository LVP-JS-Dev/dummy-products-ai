Эта документация объясняет, что это за проект, как устроен монорепозиторий и
как запускать и менять его без нарушения contract-first правил.

## Для чего этот проект

Репозиторий демонстрирует contract-first UI систему, где UI Kit является
формальным машиночитаемым источником истины. Документация и приложения
потребляют эту систему, а не определяют API компонентов.

Ключевые цели:

- показать архитектуру contract-first UI на практике
- дать машиночитаемую спецификацию UI (contracts, states, schemas, manifest)
- показать продуктовое использование UI Kit в приложении
- выпускать документацию и интерактивные примеры без дублирования API

## Из чего состоит монорепозиторий

Проект разделен на приложения и пакеты. У каждой части есть явная роль.

Основные области:

- `packages/ui-kit` — ядро системы с контрактами, states и генерацией
  спецификаций
- `packages/gen-api` — генерация typed API клиента из OpenAPI (Kubb)
- `packages/burlaki` — утилиты agent workflow, включая skill gates
- `apps/web` — продуктовое приложение, которое использует UI Kit
- `apps/fumadocs` — сайт документации на Fumadocs

## Где что лежит

Эти пути помогают быстро находить нужные файлы:

- `apps/` — приложения
- `packages/` — переиспользуемые библиотеки
- `requirements/` — требования задания и Figma-артефакты
- `docs/` — внутренние планы и заметки

В `packages/ui-kit` основные каталоги такие:

- `packages/ui-kit/src/contracts/` — контракты без React
- `packages/ui-kit/src/components/` — React-компоненты
- `packages/ui-kit/src/states/` — валидные состояния компонентов
- `packages/ui-kit/src/generated/` — схемы и `manifest.json`

В `apps/fumadocs` ключевые каталоги такие:

- `apps/fumadocs/content/docs/` — MDX-страницы
- `apps/fumadocs/src/stories/` — интерактивные Story

## Как запустить проект

Выполните команды из корня репозитория:

```bash
pnpm i
pnpm dev
```

При запуске поднимаются:

- `apps/web`
- `apps/fumadocs`

## Как работают правила

Проект использует односторонний поток истины:

- контракты формируют types
- types формируют states
- states используются в docs и apps

Нельзя определять props или states внутри docs или apps. Если требуется менять
поведение, сначала обновите соответствующий PRD.

Ключевые источники:

- системные требования: `PRD.md`
- UI Kit: `packages/ui-kit/PRD.md`
- Docs: `apps/fumadocs/PRD.md`
- App: `apps/web/PRD.md`
- процессные правила: `.ruler/agent.md`

## Design tokens

Компоненты UI Kit опираются на CSS-токены. Подключите таблицу токенов один раз
в глобальном CSS приложения:

```css
@import "@dummy-products/ui-kit/tokens.css";
```

Полный справочник токенов:

- [Design tokens](/docs/design-tokens)
