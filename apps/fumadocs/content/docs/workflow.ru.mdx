Эта страница описывает процесс изменения кода и документации без нарушения
contract-first правил.

## Сначала прочитайте нужный PRD

Перед изменениями убедитесь, что работа укладывается в существующий PRD. Если
нет, обновите PRD до начала разработки.

Используйте эти файлы:

- `PRD.md` для системных правил
- `packages/ui-kit/PRD.md` для изменений UI Kit
- `apps/fumadocs/PRD.md` для изменений документации
- `apps/web/PRD.md` для изменений приложения

## Следуйте contract-first порядку

При изменении компонента соблюдайте такой порядок:

1. Обновите контракт в `packages/ui-kit/src/contracts/`.
2. Обновите компонент в `packages/ui-kit/src/components/`.
3. Обновите states в `packages/ui-kit/src/states/`.
4. Перегенерируйте схемы и manifest через `pnpm gen`.
5. Обновите docs в `apps/fumadocs`, если изменился API.

## Соблюдайте границы

Не допускается:

- определять props или states в docs или apps
- импортировать внутренние файлы UI Kit из приложений
- редактировать generated файлы вручную

## Команды перед PR

Запустите команды из корня репозитория:

```bash
pnpm gen
pnpm test
pnpm check
```
