# PRD: Main App (`apps/web`) - Products Admin Test

## 1. Назначение приложения

`apps/web` реализует тестовое задание: административный интерфейс для работы с товарами.

Исходные требования и скриншоты: [requirements/requirement.md](../../requirements/requirement.md).

Цель приложения:

- реализовать пользовательский сценарий "вход -> список товаров -> поиск/сортировка -> добавление позиции";
- интегрироваться с публичными API DummyJSON для auth и products;
- визуально соответствовать макету Figma (экран авторизации и экран товаров).

## 2. Архитектурная роль в монорепо

`apps/web` остается приложением-потребителем и не становится источником истины для UI Kit.

Инварианты:

- приложение импортирует UI-компоненты через публичный API `@dummy-products/ui-kit`;
- `apps/web` не определяет контракты props и не подменяет `states` как source of truth;
- изменения API компонентов выполняются в `packages/ui-kit`.

## 3. Scope

### 3.1 In scope (v1)

- логин-форма с валидацией и обработкой ошибок API;
- remember me логика хранения токена;
- загрузка и отображение списка товаров из API;
- сортировка колонок с хранением состояния сортировки;
- поиск товаров через API;
- форма добавления товара (локально, без сохранения через API);
- подсветка рейтинга `< 3` красным цветом;
- базовое соответствие Figma по структуре экранов и ключевым элементам.

### 3.2 Out of scope (v1)

- собственный backend;
- собственная база данных;
- сохранение добавленного товара в API;
- сложная доменная логика за пределами требований тестового задания.

## 4. Технологические требования

- React 18+;
- TypeScript со строгой типизацией;
- работоспособность в актуальной версии Google Chrome.

Выбор state-management и UI-библиотек допускается, но должен быть обоснован.

### 4.1 Typography and token usage

`apps/web` должен использовать шрифты только через токены UI Kit:

- `--ui-font-heading` (`Cairo`) для заголовков экранов, блоков и акцентных label;
- `--ui-font-body` (`Open Sans`) для основного и вспомогательного текста;
- `--ui-font-ui` (`Inter`) для элементов управления (input/button/search/table controls).

Fallback stack задаётся токенами (`Inter`/`system-ui`/`sans-serif`) и не переопределяется локально без отдельного решения.

Пример применения:
- заголовок страницы товаров: `font-family: var(--ui-font-heading);`
- подсказка под заголовком: `font-family: var(--ui-font-body);`
- поля формы: `font-family: var(--ui-font-ui);`

## 5. Внешние интеграции

- Auth API: DummyJSON Auth;
- Products API: DummyJSON Products.

Требования к интеграции:

- ошибки API отображаются пользователю;
- загрузка данных отображает состояние прогресса;
- приложение использует реальные API-ответы для списка и поиска товаров.

## 6. Маршруты и доступ

Минимум требуются логические состояния:

1. экран авторизации;
2. экран товаров (таблица + поиск + сортировка + добавление товара).

Правила доступа:

- без валидной сессии пользователь не должен работать с экраном товаров;
- при валидной сессии доступ к экрану товаров сохраняется согласно правилам remember me.

## 7. Функциональные требования

### FR-1. Форма входа

- обязательность заполнения полей;
- отправка данных в Auth API;
- при ошибке API показывается уведомление и/или текст ошибки у полей.

### FR-2. Remember me

- если чекбокс включен, сессия переживает закрытие браузера;
- если чекбокс выключен, сессия завершается при закрытии вкладки/сессии браузера.

### FR-3. Вывод списка товаров

- список загружается из Products API;
- структура колонок соответствует макету Figma;
- при подгрузке отображается progress indicator.

### FR-4. Сортировка

- поддерживается сортировка по колонкам (минимум: цена или рейтинг);
- состояние сортировки хранится в состоянии приложения.

### FR-5. Добавление товара

- по кнопке "Добавить" открывается форма;
- обязательные поля: наименование, цена, вендор, артикул;
- при успешном добавлении показывается базовый toast;
- сохранение нового товара через API в v1 не требуется.

### FR-6. Логика отображения рейтинга

- рейтинг `< 3` подсвечивается красным цветом.

### FR-7. Поиск товаров

- поиск выполняется через API;
- результаты поиска отображаются в таблице товаров.

## 8. UX-состояния

Логин:

- idle;
- submitting;
- error.

Список товаров:

- loading;
- loaded;
- empty;
- error.

Добавление товара:

- idle;
- validation error;
- success toast.

## 9. Критерии готовности (DoD)

`apps/web` считается корректным, если:

1. Приложение запускается через `pnpm dev` и работает в актуальном Chrome.
2. Реализованы функциональные требования `FR-1..FR-7`.
3. Авторизация и список товаров используют DummyJSON API.
4. Remember me реализован с разной длительностью сессии.
5. Добавление товара работает локально и показывает toast.
6. Визуальная структура экранов соответствует макету Figma.
7. Приложение сохраняет архитектурную границу: `apps/web` потребляет, но не определяет API UI Kit.
8. Кодовая база остается со строгой TypeScript-типизацией.

## 11. Открытый вопрос

Во вводном описании задания упоминается "редактировать" товары, но в явных функциональных пунктах это не формализовано.
На текущем этапе это трактуется как неявное требование и выносится в потенциальный `v1.1` до отдельного подтверждения.
